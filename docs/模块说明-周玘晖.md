## 1. 模块边界

| 项目 | 内容 |
| --- | --- |
| 负责文件 | `backend/app/services/record_write.py`、`backend/app/routes/record_write.py`、`tests/backend/test_record_write_service.py`、`tests/backend/test_record_write_api.py` |

## 2. 公开接口

```python
create_record(payload: dict, store: JsonRecordStore) -> dict
```

处理顺序严格按规范第 8.4 节：**校验 → 生成 UUID 与 UTC 时间 → 组装记录 → 持久化 → 返回**。

- 输入 `payload` 不会被就地修改（有专门用例守住）。
- 返回值取自 `store.append_record()`，保证接口返回的就是文件里那条。
- 落盘字段固定 7 个：`id`、`date`、`type`、`amount_cents`、`category`、`note`、`created_at`。
- 金额只以整数分落盘，字符串金额不进入持久化格式。
- `id` 与 `created_at` 只由后端生成：函数重新装配字典而不沿用 payload，前端伪造不生效。

### 2.1 HTTP 状态码

| 状态码 | code | 触发条件 | 是否写文件 |
| --- | --- | --- | --- |
| 201 | — | 校验通过且已持久化 | 是 |
| 400 | `VALIDATION_ERROR` | 字段不合法、缺必填、含未知字段 | 否 |
| 400 | `INVALID_JSON` | 请求体无法解析成 JSON 对象（含数组、空体） | 否 |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | 未使用 `Content-Type: application/json` | 否 |
| 500 | `STORAGE_ERROR` | 存储读写失败，异常向上抛给统一错误处理 | 否，原文件字节不变 |

字段错误一次性定位到字段，例如 `{"fields": {"amount": "金额必须为普通十进制字符串，最多两位小数"}}`。

## 3. 三个实现取舍

1. **重新装配字典，不把请求体直接存下去。** 若直接存 `payload`，`id` 可被伪造、金额会是字符串、`created_at` 可能被前端篡改。重新装配使「id 与创建时间只能后端生成」在代码层面没有第二条通路。
2. **不在路由里重复写字段白名单。** 6 号的 `validate_record_payload` 已经拒绝未知字段（`RECORD_FIELDS`），路由再写一份就是同一规则两个来源（规范 10.1 第 2 条）。本模块只保留 415 与 `INVALID_JSON` 两个属于 HTTP 协议本身的判断，字段错误一律抛 `ValidationError`，交给 1 号 `create_app` 里的 `ApiError` 处理器。
3. **异常不吞。** try/except 吞掉 `StorageError` 只能返回假成功：用户以为记上了、文件里没有。异常原样上抛，由 1 号的统一处理器转 500，日志留在后端。

## 5. 已知限制

1. **单进程假设**：一致性由 2 号存储实例内的 `RLock` 保证；多进程/多用户需重评并发方案。
2. **幂等由前端承担**：后端不去重，连点两次会产生两条合法记录（8 号表单负责保存期间禁用按钮）。
3. **不支持批量新增**；`POST` 上的查询串被忽略，未知字段仅按 `RECORD_FIELDS` 在请求体内校验。
4. **415 / `INVALID_JSON` 的响应体在本模块内成形**（`_error_response`），未复用 1 号的处理器；两者形状已实测一致。若 1 号后续提供统一的响应构造函数，改成调用它即可，改动范围仅此一个函数。

## 6. 交接说明

`main` 上的 `create_app` 已自动注册本模块，无需任何手工步骤：

```python
_OPTIONAL_BLUEPRINTS = (('record_write', 'record_write_bp'), ...)
```

`post_record` 通过 `current_app.extensions["record_store"]` 取存储实例；缺失时抛 `RuntimeError`（属装配错误，由 1 号的兜底处理器转 500 `INTERNAL_ERROR`，不会被误当成 400）。
