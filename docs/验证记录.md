## 3. 真实服务 + 真实 HTTP

用 `Flask` 开发服务器在 `127.0.0.1:5099` 起服务，数据来自 `examples/demo_records.json`（工资 1000.00 / 餐饮 20.00 / 交通 5.00，同日，created_at 06:20、06:30、06:40），客户端用 `urllib.parse.urlencode` 编码中文参数。

| # | 请求 | 状态码 | 响应要点 |
| --- | --- | --- | --- |
| 1 | `GET /api/records` | 200 | `total=3`，顺序 06:40 交通 → 06:30 餐饮 → 06:20 工资 |
| 2 | `?category=餐饮` | 200 | `total=1`，`amount_cents=2000` |
| 3 | `?offset=5` | 200 | `items=[]`，`total=3` |
| 4 | `?limit=0` | 400 | `code=VALIDATION_ERROR`，`fields.limit="limit 必须介于 1 和 100"` |
| 5 | `?startDate=2026-11-07` | 400 | `fields.startDate="未知查询参数"` |
| 6 | `?type=&category=` | 200 | `total=3`，空串视为未填写 |
| 7 | `?type=expense&start_date=2026-11-01&end_date=2026-11-07&limit=2` | 200 | `total=2`，`items` 2 条 |

说明：响应里的中文被 Flask 默认转义成 `\u9910\u996e` 形式，前端 `JSON.parse` 后仍是"餐饮"，不影响功能；建议 1 号在 `create_app` 里设 `app.json.ensure_ascii = False` 提升可读性。

## 4. 重启后数据仍可读（三个独立进程）

隔离数据文件，不复用仓库里的样例：

```text
process1: 写入 3 条（来自 demo_records.json）  → process1 count = 3
process2: 新进程追加 1 条（交通 3.00，备注"重启验证"） → append ok, count = 4
process3: 再起一个进程读取                        → read count = 4
                                                   last = 重启验证 300
```

这一条证明的是"存储层写盘后，新进程能读到"，不是"整个应用重启能跑"——后者要等 1 号合并 `create_app` 和 `run.py`。

## 8. 顺带守住的三处边界

- `limit=²`、`offset=１` 这类 Unicode 数字：6 号的 `[0-9]+` 正则已挡住，返回 400，不是 500。
- `note` 缺失或为 `null`：存储层在写入与读取两侧统一补成空字符串，避免前端插值显示 "null"。
- 未知查询参数（含驼峰写法）：路由白名单直接 400 并定位字段，不静默忽略。
