# 5 号王圣杰：统计计算模块交接

统计模块遵循[项目设计与协作规范](项目设计与协作规范.md)中的筛选口径、
金额单位、HTTP 响应和模块边界。

## 公开接口

- `backend/app/services/statistics.py`
  - `summarize_records(records, filters) -> dict`
  - 复用查询模块的 `filter_records`，统计全部匹配记录，不接收分页参数。
- `backend/app/routes/statistics.py`
  - `GET /api/statistics`
  - 接受 `start_date`、`end_date`、`type`、`category`、`min_amount`、`max_amount` 六个筛选参数。
  - 明确拒绝 `limit`、`offset` 和未知参数，避免调用方误以为统计只覆盖一页。

## 响应字段

成功时返回 `data.income_cents`、`data.expense_cents`、`data.balance_cents`、
`data.count`、`data.income_count`、`data.expense_count` 和
`data.expense_by_category`。金额均为整数分；类别汇总只包含支出，按金额降序、
同金额按类别名称排序。

## 依赖与接入

- 依赖 4 号高一鹏的
  `backend.app.services.record_query.filter_records(records, filters)`。
  统计模块不从 HTTP 查询接口取数，也不重复实现筛选。
- 依赖 6 号黄俊凡的 `RecordFilter` 和 `parse_filters`。
- 1 号叶凯乐在应用工厂中注册 `statistics_bp`，并确保
  `app.extensions["record_store"]` 提供 `list_records()`。
- 路由只读取一次存储快照，然后交给统计业务函数。

```python
from .routes.statistics import statistics_bp

app.register_blueprint(statistics_bp)
```

`statistics_bp` 已包含完整 `/api/statistics` 路径，注册时不要再添加 `/api` 前缀。

## 验证

```powershell
python -m pytest tests/backend/test_statistics.py -q
```

覆盖基准数据、负结余、整数分精度、类别聚合与同金额排序、无匹配记录、
无关分页参数拒绝，以及一次请求只读取一次存储快照。

## 当前限制

- 4 号查询服务尚未合入时，单元测试用隔离的筛选替身验证统计契约；统计路由应在
  4 号 `filter_records` 合入后执行真实联调。
- 当前设计是单机单用户，不对一次统计期间的外部数据更新提供快照事务保证。
